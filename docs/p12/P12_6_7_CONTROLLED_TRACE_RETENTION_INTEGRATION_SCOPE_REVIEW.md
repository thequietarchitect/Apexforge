# P12.6-7 — Controlled Trace-Retention Integration Scope and Coverage Review

Outcome: PASS for a bounded integration scope, not universal trace coverage. P12.6-6 is the validated predecessor and remains unchanged. This review creates one document only. No attachment, instrumentation, AIR/result/profile/compiler/TAM/authority/PDB change or later gate is started.

## Live pipeline census and attachment decisions

### Compiler/tooling

language.lexer.lex produces tokens. language.parser.parse_source_unit calls lex and Parser.parse_source_unit internally; it does not return its token stream. compile_source_with_map returns CompiledSource(program, SourceMap); compile_source returns AIR only. The opt-in compile_source_with_operation_evidence returns CompiledSource plus the actual compiler ledger for one directive. The compiler's existing state/action construction hooks are the correspondence producer. Use this opt-in API once, then the normal AIRVerifier.verify(...).require_verified() and tooling.source_air_mapping.source_air_mapping to build a validated external tooling wrapper. Do not recompile or relex simply to populate absent evidence.

P12.6-8 may add an opt-in tooling build wrapper containing governed SourceIdentity/bytes snapshot reference, CompiledSource, ledger, verified AIR, SourceAIRMapping, and supplied TAM collections. Produce the SourceMap TAM projection through the existing adapter at that return boundary; associate operations only through exact ledger/sidecar evidence. Existing compile_source, compile_source_with_map, CompiledSource and parser APIs remain unchanged. Token TAM is available only if the actual lexer tuple was supplied by its owner; automatic token capture would require a new parser producer seam and is deferred. Type/resolution/authority/narrative adapters do not justify recomputing their underlying analyses.

ProjectBuilder.build is a different path: normalize sources, analyze modules/mask headers, _compile_unit, merge maps, build declaration metadata, validate visibility, link programs, RuntimeValidator.validate, resolve entry, build resolution candidates, return ProjectBuild. Its custom compiler contract accepts CompiledSource or bare AIR (empty map), not the operation-ledger tuple. ProjectBuild contains maps/identities/ownership but not that ledger. It may be referenced by an external tooling wrapper for already-existing evidence. General linked/multi-source operation correspondence is NOT available: P12.6-4 supports only original single-directive AIR, and masking/linking can change governed correspondence. Never zip project SourceMap entries to linked AIR or transplant a pre-link map under a new hash. Project compiler dispatch, linker and ProjectBuild schemas stay unchanged in P12.6-8.

### Verified AIR and plan

AIRVerifier returns VerificationResult, require_verified returns VerifiedAIRProgram. Project builds instead use language.validation.runtime_validator.RuntimeValidator.validate. Keep their verification behavior and wrappers intact; the observer consumes the already-returned canonical wrapper. workflow.air_runner.build_registry_execution_plan constructs/relinks reachable programs and returns RegistryExecutionPlan(program, entry_directive, directive_owners). It is not an automatic step of every project build or direct runtime call. run_air_from_registry builds the plan, then run_air_program verifies its program and builds default context; ProjectBuild.execute directly calls RuntimeEngine.execute without constructing a registry plan.

Tooling constructs a separate execution association AFTER the actual plan exists, using build_verified_air_lowering_input, bind_registry_execution_plan and MetadataAssociation.for_plan, and carries it alongside verified AIR/plan/source evidence. Required bindings are exact AIR, sidecar, routing/entry and owner fingerprints; MetadataAssociation adds owner content hashes not independently covered by the general routing hash alone. Revalidate on transition into execution and on result attachment. Lifetime is one explicitly governed execution request; build-side metadata may be shared immutably. The association is optional for existing APIs, required in the opt-in retained path. Changed linked AIR/owner/entry/source invalidates it; refuse attachment rather than rehashing an old map. Neither VerifiedAIRProgram nor RegistryExecutionPlan owns trace payloads. Existing plan construction uses representation identities internally; those must never enter trace fingerprints.

### Managed/core runtime

RuntimeEngine.execute(verified, context, entry_directives, directive_entry_guard) constructs local traces, runs canonical owners, and returns runtime.engine.ExecutionResult(delta, Trace, sorted diagnostics, final_state). There is NO production conversion from that result to native_backend.CanonicalExecutionResult; repository call sites produce the latter only in native _decode. Do not invent a managed canonical-result adapter to satisfy a diagram.

The acceptable non-instrumented attachment is a new opt-in tooling execution wrapper: validate input association/context, invoke the existing runtime exactly once, consume its returned Trace/diagnostics directly, and return an external observational wrapper. This is producer-return retention, not a new event-production callback. RuntimeEngine.execute has no trace observer callback today. Do not add an arbitrary callback into authority/evaluation/action loops. Preserve the original result unaltered, including unsupported events and diagnostics. Complete-retention requests with unsupported kinds must fail explicitly; an explicitly requested supported subset must have a coverage manifest distinguishing retained and unsupported records, never masquerade as full coverage.

| Producer handoff | Known identity now | Absent identity / constraint |
| --- | --- | --- |
| runtime.start/finish at execute | AIR from verified input; invocation scope; final Trace tuple index | No operation or source span; finish is owner observation, not unconditional success |
| directive.start/finish/skip | directive ID and depth from runtime inputs/facts | No typed directive OperationReference; recursive invocation occurrence not represented by depth alone |
| CausalSelection consumed in _execute_directive | actual decision object, selected path object, caller directive/decision loop | CausalEngine alone lacks directive occurrence/global AIR scope; supported typed metadata locators do not represent a path-selection operation |
| authority.check immediately after context.authority.allows(check) | actual check object/ID and supplied allowed value | Complete policy context fingerprint absent for arbitrary policies; no OperationReference |
| state.delta in _execute_ordered_actions | directive/decision/path objects, local action_index, actual evaluated assignment | Trace lacks assignment occurrence; local action index is not canonical assignment index; nested/invoked action origins differ |
| when/event/effect observations | actual supplied facts and current owner execution scope | Missing general action locators; no inference from values or event strings |
| diagnostics in returned ExecutionResult | severity/code/node ID; sorted producer-return ordinal | Emission chronology is lost in sorting; node ID is not a physical span or supported operation locator |

P12.6-6 schemas cover a bounded event subset, not function/invocation/error events generally. The integration must preserve raw results and report that boundary. Validation failures are separate observation errors with the original owner result accessible; they must not flip semantic ok/status or trigger execution replay.

### Causal and authority owners

CausalEngine.select_path(decision) knows the exact decision and selected path and returns CausalSelection with causal.evaluate/select records. Retain those returned records, not a fresh call to select_path. RuntimeEngine already appends them into its trace; return-boundary integration can preserve that original position. A future producer handoff could carry explicit directive index/ID, decision occurrence and selected path index/ID plus AIR fingerprint. That is an observational association, not a chooser. No supported P12.6 path-selection locator or operation ID currently exists; retain at execution/AIR scope. A source-map reference requires positive producer evidence, not name matching.

RuntimeEngine invokes the supplied authority policy exactly once per check and records its returned allowed boolean. The observer may retain that check/decision record and existing passive TAM check/grant evidence separately. AuthorityEngine owns grant evaluation; AuthorityPolicy supports arbitrary implementations and has no identity protocol. No re-check, adapter-made allow/deny, or fabricated default approval is permitted. Where explicit policy identity is unavailable, label policy-context provenance unavailable and refuse a complete execution-context assertion. A check SourceMap position may be synthetic directive-origin evidence, not a physical policy-decision span.

Until a separately authorized producer change, retain state.delta at execution scope. Future explicit occurrence emission is possible without duplicating semantics only if canonical producers supply: exact AIR fingerprint; directive index/ID; decision-reference occurrence/ID; selected path index/ID; root action position and nested branch/action lineage; assignment-list occurrence where applicable; and invocation frame occurrence for repeated calls. ## Narrative path

Canonical narrative build material is validated by tooling.narrative_execution.load_narrative_execution_material; request loading produces NarrativeExecutionRequest(state, choice, path_index). execute_narrative_request delegates exactly once to runtime.narrative_observability.execute_narrative_choice, which delegates transitions to runtime.narrative_transition and returns NarrativeExecutionResult with trace, diagnostics and choice evidence. terminate_narrative returns termination state, not a new trace event.

Natural external attachment points are validated material/request plus the returned result. Existing narrative_execution_request_payload, narrative_execution_result_payload/bytes and canonical build-artifact fingerprinting provide stable owner serialization inputs; preserve separate narrative chronology. Events have kind/facts but no standalone record ID; P12.6's ordinal/payload identity can distinguish them once a justified scope exists. Their selected_path_index is a narrative path index, never an AssignmentLocator.

A standalone narrative build legitimately has no AIR. P12.6-6 ProvenanceScope requires AIR; NarrativeEvidence type support does NOT establish a sound standalone narrative scope. Do not use unrelated AIR, a zero/hash sentinel or synthetic AIR. Record this as an AIR-free scope/association coverage gap. Standalone automatic narrative retention is deferred in P12.6-8 pending a separately reviewed additive narrative-input envelope; existing narrative serialization/result stays unchanged. Mixed artifacts alone do not establish a narrative-to-AIR correspondence.

## Native pre/post-dispatch

native_execution_contract.admit_native_profile remains admission authority. native_execution._source lowers admitted state initializers/stores; source_mapping.emit_native_source_mapping delegates to admission and that emitter's region side channel. build_native_with_mapping returns MappedNativeArtifact around the normal build_native artifact and receipt. No new C comments, flags, addresses or runtime events are needed.

Opt-in native orchestration can automatically retain, before dispatch, exact verified AIR, MetadataAssociation routing/owners, optional valid source/AIR mapping, NativeSourceMapping, profile, generated-C digest and mapped artifact/receipt/image. Admission still precedes build side effects. Metadata cannot admit ordinary compiler output with nonempty actions/authority surface, and absent ApexForge source remains UNMAPPED_SOURCE. Do not silently remove actions or require fabricated source maps.

Call dispatch_native once on the actual backend-issued artifact. It re-admits, checks issuance/receipt/input, locks and hashes the image, executes _run, decodes captured bytes, and returns NativeExecutionEvidence with CanonicalExecutionResult/receipt/output digest. Attach NativeEvidence collection and NativeResultAssociation after that return using exact actual evidence. Validate the association while image/mapping are still available. Preserve the existing lock/ticket enforcement; do not use a trace store as artifact authority.

execute_native uses a temporary directory and deletes the image on return. A retained wrapper must perform the normal build/dispatch/association within its governed directory lifetime, then retain immutable digest/evidence snapshots, not a dangling promise to validate a deleted image. Reuse owner build/dispatch APIs; do not read arbitrary paths to recover missing metadata. Native failures/timeouts/malformed output raise NativeExecutionError; no successful evidence/result is produced. Retain the supplied error code/detail externally if desired, preserve the exception and do not synthesize a FAILURE CanonicalExecutionResult or finish/per-operation event. Current P12.6-6 native-family schema supports successful returned evidence, not a comprehensive native failure collection; failure-model extension remains deferred.

## Deterministic execution context and chronology

One semantic execution is one owner invocation with its explicit governed inputs/configuration. AIR/routing/map hashes alone are insufficient for managed execution. A complete managed context needs exact initial StateSnapshot cells with typed values; entry selection; policy data/identity; causal owner contract; standard-library behavior identity; invocation-depth/configuration; any directive-entry guard; and applicable owner-program references. ExecutionContext contains only state and AuthorityPolicy. RuntimeEngine also permits custom causality/standard library; arbitrary callables/policies have no deterministic identity protocol. Never hash repr, memory addresses, callback bytecode or a machine environment to fill this gap.

P12.6-8 may define an additive tooling execution-input fingerprint preimage only for the known default owner contracts: actual explicit immutable state, exact AuthorityEngine grant tuple, default CausalEngine/default standard library governed contract identities, canonical plan entry, explicit depth limit and no custom entry guard. The orchestration constructs/receives those exact inputs; it does not probe a policy or evaluate initial expressions to fingerprint them. Canonical owner labels are versioned compatibility contracts, not invented implementation-authentication hashes. Custom policies/engines/libraries/guards without owner-supplied provenance remain unsupported for complete retained execution association. Source scope is not relabeled as complete runtime context. Metadata-only context encoding tests must precede managed wiring.

Native context can use exact AIR/routing/native map/profile/receipt/image plus governed input correspondence; the profile has no extra semantic input beyond its admitted program. Timeout/capture policy may be retained as explicit operational request configuration to distinguish completion/failure observations, without making clocks/environment semantic inputs. Narrative context would bind validated material and exact request/state via their own owners, not AIR.

Identical legitimate executions should share deterministic content-context identity. There is currently no canonical owner of a physical run ordinal: do not invent one. If a future explicit ordered batch owner supplies an invocation ordinal, bind it to the governed batch identity. Producer event ordinal is local to a returned stream, not a run/session ID.

No global chronology is needed. Core, causal and authority observations are already interleaved in the RuntimeEngine returned Trace; an external partition manifest can preserve each family's original indices as references to that parent tuple, alongside P12.6-6 family-local ordinals. It must not reconstruct lost indices from equal values. Diagnostics retain their producer-sorted order, not emission chronology. TAM order is compilation/evidence order; narrative is request/transition order; native has only validated pre-dispatch and returned post-dispatch causal boundaries. Across independent families use explicit lifecycle links/partial order, never timestamps or a fake global clock.

## API compatibility, lifetime and security

Choose additive opt-in tooling functions and frozen external wrapper types. Do not change default compiler APIs, ProjectBuild compiler return contracts, RuntimeEngine/CausalEngine/AuthorityPolicy signatures, narrative results, native build/dispatch return values, receipts or CanonicalExecutionResult. Existing callers see identical behavior. Internal semantic loops need no callbacks for returned-record retention. Token capture, richer runtime occurrence emission, AIR-free narrative scope and failure schemas would require distinct reviewed additive contracts, not hidden compatibility changes. Unsupported requests must fail explicitly at preflight where knowable; validation of actual returned evidence can fail after execution without changing the owner result or retrying.

Retain source snapshots/SourceMap/ledger/AIR/validated mapping once per build; share immutable references. Per execution retain context, family collections, original-index partition references and result/artifact association digests. Do not duplicate maps/receipts/source text in every record. Current validation frequently reserializes AIR, regenerates mapping evidence, hashes sidecars and constructs SourceText per record; estimate possible O(records * source-or-AIR-size) work, with operation validation potentially quadratic on large graphs. This is static complexity inspection, not a benchmark. Native image hashing has image-size cost. Runtime recursion/functions can create large existing traces; history accumulation across runs is especially unbounded. P12.6-8 needs explicit caller-owned per-request retention limits and a visible unsupported/resource-limit outcome; never silently truncate a collection while retaining its complete fingerprint. P12.8 performance/memory closure and optimization are not undertaken here.

Use governed byte snapshots/validated owner objects, not file-name-driven discovery. Reject paths in canonical identity fields; keep existing local error display text outside canonical export. No environment dumps or source content in errors by default. Do not deserialize an arbitrary producer label into an executable producer, accept forged labels as authenticity proof, scan disk for missing evidence, or add ambient registries/singletons/thread-local trace state. A supplied hash is integrity identity, not a producer signature. Preserve native issuance checks (its existing weak ticket registry is backend-owned, not a proposed trace registry). Validate sidecar/source/AIR/plan/map/image/receipt/result substitutions at explicit boundaries, including after mutable plan owner dictionaries change. Retention limits and exact family/schema allowlists guard amplification. Wrappers own references locally and return them explicitly; no host-global mutable trace injection.

## P12.6-8 ordering and exact scope

1. Add opt-in single-directive compiler/tooling wrapper using the existing ledger path and SourceMap TAM adapter; retain supplied additional TAM only where validated. No token replay or project-wide mapping extension.
2. Add explicit verified-AIR/plan association wrapper, exact owner/source validation and stale-boundary negatives. Reject changed/linked AIR lacking producer correspondence.
3. Establish the bounded default managed execution-input/context contract described above, then retain existing supported returned events/diagnostics via one runtime invocation. Add parent-stream partition indices without new runtime events; preserve unsupported raw records and explicit coverage. No canonical-result conversion or runtime operation associations.
4. Review narrative input/return boundary; defer automatic standalone narrative attachment until an AIR-free scope contract is separately authorized. Do not invent AIR to keep this sequence moving.
5. Add opt-in native build/pre-dispatch and post-dispatch retention using actual existing mapped artifact and evidence, with association completed before temporary cleanup. Preserve exceptions and explicitly unsupported failure-record coverage. No per-operation trace.
6. Run focused integration acceptance, all predecessor P12.6/P12.5 regressions and targeted producer compatibility checks; test optional/off behavior, determinism, limits, substitutions, unknown context/schema, exact call counts and no semantic replay.

This is the complete allowed P12.6-8 implementation recommendation, not work started here. Custom-context provenance, full event schemas, linker/source correspondence, narrative scope extension, runtime occurrence instrumentation, native failure schemas and debugger/PDB/address work remain deferred. If a permitted stage cannot satisfy its context/provenance preconditions, report the classified coverage gap rather than broadening semantics.

## No-second-semantics audit and inspection evidence

The design calls compiler/verifier/plan/runtime/narrative/native owners only to perform the requested canonical work once. Retention receives their actual outputs; it never resolves, infers, evaluates, selects, enforces policy or decodes decisions itself. Existing mapping validators validate explicit references. No assignment occurrence reconstruction, operation matching from values, inference of execution from C membership, global chronology fabrication or action reordering is permitted. New instrumentation is not needed for the defined bounded attachment scope and is not authorized.

Inspected live compiler, lexer/parser, project build/link/verification calls, AIRVerifier, language.validation.runtime_validator, workflow.air_runner, runtime.engine/context/state, causality.engine, authority.engine, standard_library.registry, narrative execution/observability/tooling serialization, native execution/mapping/plan binding, and P12.6 trace retention model. Production call-site search confirms native-only CanonicalExecutionResult creation. Two read searches referenced nonexistent guessed validator/dispatch paths; corrected inventory located the actual validator and native execution functions. These were read-search invocation issues, not test or implementation failures.
