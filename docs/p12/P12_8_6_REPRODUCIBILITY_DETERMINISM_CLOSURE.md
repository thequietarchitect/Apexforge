## Test implementation and ownership

`p12_8_6_reproducibility_determinism_test.py` is test-only. It imports existing observer,
AIR verifier, compiler metadata producer, mapping/build/dispatch owners, retained
RuntimeEngine owner and P12.7 comparators. Native positive calls are real, with
RuntimeEngine.execute trapped only during native operations. No mocked positive native
execution, fallback, independent decoding or assignment evaluator is introduced.

The base fixture is the frozen two-state overwrite/untouched case. Scale points reuse
the unchanged P12.8-4 workload constructor. Canonical AIR execution alone supplies
expected final projections. Independent objects include programs/state nodes, verified
wrappers, plans, contexts, source metadata/mappings and artifacts. Same immutable input
values are legitimate; merely retaining a single mutable object is not the test method.

Each root is declared explicitly by its test owner and starts empty. Native IRR child
directories own generated C/image/object/discovery/capture products until DBL. Artifact
wrapper/ticket ownership is released separately. Numeric/text comparison reports and
two image-byte buffers per load point are intentional bounded DHF/CER test evidence,
never live process handles. Existing AIR/routing/profile fingerprints are SHR continuity
identities. The observer only measures these resources; it never grants execution authority.

## Reconstruction families

### A–D: fresh objects, process instances and clean roots

The base probe runs once in the test process and twice in separately launched LYRA
Python processes, each under a different empty owned root. Child hash seeds are 97
and 194; the parent retains its ambient seed. Children use the same interpreter with
`-X utf8 -B`, structured shell=False launch and a finite probe timeout. No new dependency
or persistent report file is used. Each child independently reconstructs, verifies,
plans, emits, builds, dispatches, retains, revalidates and cleans the fixture.

Full deterministic reports must equal across all three process/root combinations.
Comparisons include AIR transport/form/hash, plan/routing/profile, C and mapping form/hash,
canonical and managed result identities, managed trace collections, source compiler
metadata/TAM records, full native image bytes (hex transported without normalization),
full receipt, output/native result, retained native trace/pre/post/provenance and residue.
Process/root uniqueness is witnessed for this run, not made a canonical identity rule.
After each child exits, its root is empty; the owning outer TemporaryDirectory then
removes it. Tickets return to the original issuance baseline without forcing GC.

### E–G: source, metadata and traces

Independent AIR/plan reconstructions regenerate C and native mapping; built program.c
bytes are checked against the emitter, with exact mapping equality. Three additional
independent compiler metadata reconstructions use the same exact SOURCE bytes and
logical name `src/main.apex`; source mapping canonical form, sidecar canonical identity,
compiler/mapping fingerprints, TAM collection and record identities must match.
Operation/region ordinals retain canonical producer order. Arbitrary semantic/source-map
reordering is not permitted merely to manufacture construction-order variation.

The source compiler fixture contains real causal actions; it is used only for metadata
and is never sent to native or stripped. Native hand-built fixture mapping legitimately
uses UNMAPPED_SOURCE with AIR-operation/generated-C correspondence. These are distinct
surfaces, not a fabricated source-to-native bridge.

Managed/native/TAM retention in these contracts is content-addressed and scope/revision
bound. Equal reconstructed content may have equal record identity across process
instances. Ordinals distinguish repeated occurrences within a collection; diagnostics'
display strings can be excluded only under existing owner contracts. This test does
not invent unique run IDs or demand native intermediate-operation traces. If a future
carrier adds instance-specific identity, it must be evaluated under its own contract.

### H: conditioned native build reproducibility

Frozen P12.5 tests explicitly require equal PE image bytes and receipts for identical
input/toolchain; therefore this stage tests that stronger property locally. Every
base process report includes the actual image bytes/hash and full receipt. The existing
toolchain discovery is compared to actual receipt tool hashes and supplies the compiler
banner. No volatile fields are removed from any binary or canonical receipt before
comparison. Exact C/image/receipt equality across fresh roots is conditional, not a
claim across compiler versions, target platforms or machines.

### I: representative supported load

At 1, 64 and 256 states (same count of stores), two independently constructed objects
under two fresh roots each execute canonical, managed-retained and real native paths.
AIR form/hash, plan/routing/profile, generated C/native mapping, complete projections,
raw canonical order, managed identity, image bytes, receipts, output and cleanup
inventories must match. Native at these points uses existing mapped build and canonical
dispatch directly, rather than adding the expensive native-retention audit benchmark;
native-retained provenance is compared in the separate base process probes. All actions
and frozen admission conditions are preserved. This samples the primary dimension,
not the full 256-state/4096-store Cartesian domain.

### J: rejection determinism

Three fresh reconstructions of each selected verified but unsupported input (an extra
explicit BOOL state and add_int assignment) must reject with NATIVE_PROFILE_UNSUPPORTED.
Compiler discovery and RuntimeEngine fallback are failure-trapped; no build files or
issuance entry may appear, and canonical transport remains unchanged. Free-form
exception messages are not forced equal. Unsupported native inputs remain
NATIVE_PROFILE_LIMIT, not semantic failures of the broader canonical language.
